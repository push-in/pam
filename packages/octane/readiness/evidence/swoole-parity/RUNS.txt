14. Follow-up: Whoops noise after a memory_limit fatal (fixed, df168dbe).
    Cause: the fatal cuts the request before PAM resets the SAPI response,
    leaving a raw HTTP/ status line. At worker exit Laravel's shutdown
    handler re-handles the fatal (and logs it, which is wanted), Collision
    then registers Whoops, and Whoops' http_response_code(500) became a PHP
    8.5 warning and an "Uncaught Whoops\Exception\ErrorException" fatal.
    PAM now resets the response state before PHP shutdown. Check: /_r/oom and
    a task-worker OOM, then the server error log: 0 "Uncaught", 0 "Couldn't
    execute"; the memory_limit fatals are still logged once each.
